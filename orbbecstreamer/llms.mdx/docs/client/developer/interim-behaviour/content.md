# Contract gaps and interim behaviour (https://irc-hslu.github.io/orbbecstreamer/docs/client/developer/interim-behaviour)



Some behaviour on the user pages depends on questions the protocol contract (`protocol/wire-format.md`) hasn’t settled yet. The client picks one reading in the meantime, marked `INTERIM` in the code, and the mock server follows the client’s proposal. A real server may behave differently until the arbiter decides. This page lists each gap that users can notice, with its change request in `protocol/changes/`, and the requests the arbiter has since decided.

## Decided by the arbiter (protocol #383, 2026-10-17) [#decided-by-the-arbiter-protocol-383-2026-10-17]

These were gaps on this page. The client now follows the contract, except where a row names what remains.

| Topic                                            | Change request                    | What the client does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | User page                                                                                                                  |

| Empty media streams and the end-of-stream record | 0004, accepted                    | A stream finished before its header is `frame-truncated`. A record has `endOfStream` set exactly when its payload is empty, and then no other flag; anything else is `invalid-message` and fails that server’s session.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Not visible beyond the card’s close reason.                                                                                |
| Integers in control JSON                         | 0005, accepted                    | Every integer in a control message has magnitude at most 2^53−1; microsecond fields are in \[0, 2^53−1]. A larger value is `invalid-message`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Not visible.                                                                                                               |
| Replies, `replyTo` and the lock expiry           | 0008, accepted                    | Each request gets exactly one reply, after the broadcasts it causes. With a minor-1 server the client recognises its own calibration result and placement update by `replyTo`; without it, by its pending request. A refresh for cameras, bundles or quantization asks with `revision-refresh` (minor-1 servers only). Another client’s lock expiry is still the one the server last announced: the server re-announces it when a renewal moves it by at least 1 s.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | [Read a server card](/docs/client/server-card#details): `expiry passed as last announced; the server may have renewed it`. |
| HEVC payload format                              | 0010, accepted                    | Annex-B access units with VPS, SPS and PPS in every keyframe record; no `hvcC`; the decoder is configured from `codecString` alone. Each codec-config record’s SPS is checked against the channel’s `codecString`, which must be the `hev1` form of the SPS `profile_tier_level` (trailing zero constraint bytes omitted, §6). On a mismatch, or with no SPS, that channel’s decoder is not configured, the bundle is undecodable and the log names the reason (`level`, `profile`, `tier`, `constraint-bytes`, `hvc1`, `no-sps`, …). Vectors: `protocol/vectors/codec-string/`.                                                                                                                                                                                                                                                                                                                                                                                                                     | A live server’s card shows **decoder failed** for that bundle.                                                             |
| Coordinate frame and pixel centre                | 0011 option A, accepted           | Metres, **left-handed**, +X right, +Y up, +Z forward (§9). A depth pixel’s centre is at its integer coordinate, v down: `pointDepthCamera = ((u − cx)·z/fx, −(v − cy)·z/fy, z)`. Tile-view overlays (`tileToCss`) use the same pixel convention.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | [Move around the 3D view](/docs/client/viewer): a mirrored cloud is a server or recording that does not convert its poses. |
| Wire poses                                       | 0022, accepted                    | The server sends camera poses already in the §9 frame (C·M·C, C = diag(1, −1, 1, 1)); the client applies them as they are. The `geometry-*` conformance vectors pin the result with a non-identity pose.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Same row as above.                                                                                                         |
| Meaning of a calibration result                  | 0012 superseded by 0023, accepted | A solved run stays `running` and waits for Commit; with a minor-1 server its `awaitingCommit` says so, otherwise the message (`… awaiting commit`). `server.calibration.result` is sent only on a commit (in force at once) or a failure. Cancel, leave, lock loss and disconnect abandon the run: nothing is committed and no result is sent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | [Calibrate depth](/docs/client/calibration) and [Set up a server](/docs/client/setup-workspace).                           |
| Recording manifest                               | 0038, accepted                    | Reads a recording folder with `manifest.json` version 1 (Appendix B; schema `protocol/schema/recording-manifest.json`): relative file paths, per-bundle segments, in-progress trimming, cameras sent on one timeline by frame set index, and handed to the 3D view together only at equal index (B.5). Two client departures from B.5 remain: a frame set waits at most 100 ms for every camera that has a frame there (`src/media/playback/frameSetHold.ts`; B.5 sets no bound), then hands over the cameras it has; and the hold aligns the hand-off to the renderer, not the frame drawn, so after a timeout the missing camera’s previous frame stays visible next to the newer ones. A newer complete frame set drops older waiting ones, and a frame of an index already handed over is late and dropped; both count as dropped on the card. A manifest without `manifestVersion` (the pre-0038 format) is refused, as B.2 requires, with a message that names `scripts/convert-manifest.mjs`. | [Play a recording](/docs/client/playback).                                                                                 |

Error codes such as `not-lock-owner`, `calibration-running`, `calibration-not-running` and `stale-revision` are the mock server’s own. The contract doesn’t fix server error codes for these cases, so the user pages quote them only as the mock server’s. Protocol 1.1 names `lock-held`, `invalid-lease`, `role-required` and `rate-limited` (§11).

## Protocol references still on screen [#protocol-references-still-on-screen]

None. The UI strings in `client/src/ui/` carry no change-request numbers or § references. The last two messages that cited the contract now say the rule in plain words (2026-09-28):

* `Not applied: The pose must be rigid: scale, shear, mirroring and perspective are not allowed.` comes from `client/src/calibration/placementDraft.ts` (§9 requires placements to be rigid transforms). The placement fields and handle can’t produce such a pose.
* `depth bitstream has 8-bit luma; depth must be 10-bit` comes from `client/src/media/playback/recordingManifest.ts` (§8 defines depth as one 10-bit code per pixel).

## Keep this page current [#keep-this-page-current]

When the arbiter accepts or changes one of these requests, move its row to the decided table and update the matching user page in the same PR. The client’s full list of interim decisions is in `client/docs/development/ROADMAP.md`, and the mock server’s is at the top of `client/src/media/playback/mockServer.ts`.
